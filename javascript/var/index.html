var e hoisting — aula profunda e visual

0. O que é uma variável?

  • Em JavaScript, uma variável não é uma caixa que guarda valores. Ela é um identificador registrado no ambiente léxico, que aponta para um endereço de memória.

  • O ambiente léxico é a estrutura interna do JavaScript responsável por registrar os identificadores, definir o escopo onde eles existem e manter a referência ao valor armazenado na memória.

1. Declaração com var

var name =
console.log(name) → "Sanciweferson"

Antes de qualquer linha rodar, o JavaScript faz uma fase invisível chamada fase de criação. Nela, o motor já cria a variável name e coloca o valor undefined na memória. Só depois, na fase de execução, o valor "Sanciweferson" é atribuído. O hoisting acontece aqui, mas como você acessa a variável só depois da atribuição, ele passa despercebido.

2. Redeclaração silenciosa

var name =
console.log(name) → "San"
var permite declarar a mesma variável mais de uma vez no mesmo escopo. O motor verifica: a variável já existe? Se sim, ele ignora a nova declaração e executa apenas a atribuição. Não há erro, aviso ou proteção. Esse comportamento é um dos principais motivos do var ser considerado perigoso em código grande.

3. Reatribuição

name =
console.log(name) → "Weferson"
Aqui não existe uma nova variável. Apenas o valor apontado por name é trocado. Variáveis em JavaScript funcionam como etiquetas que apontam para valores na memória. Trocar o valor não muda a variável, apenas o conteúdo referenciado.

4. Hoisting básico

console.log(hoist)
var hoist =
Resultado →
Antes de qualquer linha ser executada, o JavaScript entra na fase de criação. Nessa fase, o motor já encontra a declaração var hoist e cria a variável na memória, mas sem valor. Por isso, ao executar console.log(hoist), o resultado é undefined. Só depois, na fase de execução, a atribuição acontece. O hoisting não move o código fisicamente: ele apenas garante que a variável exista antes da execução começar.

5. Hoisting em função (shadowing com var)

Quando usamos var dentro de uma função, a declaração da variável é movida para o topo do escopo da função (hoisting). Isso faz com que a variável local exista desde o início da execução, mesmo estando declarada depois no código.

var valor = 100; function teste() { return valor; var valor = 10; } console.log(teste());

Internamente, o JavaScript interpreta a função assim:

function teste() { var valor; return valor; valor = 10; }

A variável valor declarada com var dentro da função cria um novo escopo local, que sombra a variável global (valor = 100). No momento do return, essa variável local ainda não recebeu valor, então o retorno é undefined.

Resultado no console → undefined

⚠️ Observação importante: o valor retornado pela função só aparece no console porque foi usado console.log(teste()). Chamar apenas teste() executa a função, mas não exibe o retorno.

Dentro da função, o motor cria primeiro: var valor;

Essa variável local esconde a variável externa.

Mesmo sem valor atribuído ainda, ela já existe e retorna undefined.

Esse fenômeno é chamado de shadowing (sombreamento).

8. Closure com var

var funcoes = []
for (var i = 0; i < 3; i++) {
  funcoes.push(function () { return i })
}
console.log(funcoes) →
Todas as funções fecham sobre a mesma variável i.

Quando o loop termina, i vale 3.

Closure não copia valores, ela mantém referências vivas na memória.

9. Closure correto usando var

for (var i = 0; i < 3; i++) {
  (function (valorAtual) {
    funcoes.push(function () { return valorAtual })
  })(i)
}
console.log(funcoes) Resultado: →
Cada execução da IIFE cria um novo escopo.

O valor de i é copiado para valorAtual.

Assim, cada função fecha sobre uma memória diferente.

10. Garbage Collector

var lixo = "memória"
lixo = null
Estado → sem referência
O Garbage Collector remove valores que não podem mais ser alcançados.

A variável continua existindo, mas o valor antigo não tem mais nenhuma referência.

Se uma closure ainda apontasse para esse valor, o GC não poderia removê-lo.
